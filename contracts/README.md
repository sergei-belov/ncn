# Общий контракт микросервисов NCN

Этот каталог содержит контракты двух находящихся в разработке микросервисов: `ncn-agents` и `ncn-pms`. Этот файл кратко фиксирует их назначение и границу ответственности; подробные требования определяются контрактами сервисов по ссылкам ниже.

## Микросервисы

| Микросервис | Назначение | Владеет |
| --- | --- | --- |
| `ncn-agents` | Регистрация и настройка ИИ-агентов, выполнение пользовательских и системных запросов, оркестрация координатора и работников | Конфигурации агентов, Sessions, Messages, Runs, планы выполнения, usage и жизненный цикл агентного запуска |
| `ncn-pms` | Управление проектами и работой внутри workspace | Проекты, состояния/колонки, карточки (`WorkItem`), эпики, их связи, порядок и прогресс |

## Граница ответственности

- `ncn-pms` является источником истины для проектных сущностей и их бизнес-инвариантов.
- `ncn-agents` не хранит копии проектных сущностей как собственное бизнес-состояние и не изменяет их напрямую.
- Агент читает и изменяет проектные данные только через разрешённые API/MCP-инструменты `ncn-pms` с обязательной проверкой прав.
- Для асинхронных сценариев сервисы обмениваются доменными событиями через Kafka; PostgreSQL каждого сервиса остаётся источником истины для принадлежащих ему данных.
- Межсервисные запросы и события должны сохранять `workspace_id`, `project_id` и correlation identifier для изоляции, идемпотентности и аудита.

## Контракты и статус

- [`agents/`](agents/README.md) — архитектурный контракт мультиагентного ядра; нормативные инварианты имеют приоритет над деталями проектирования и реализации.
- [`pms/`](pms/plane-project-management-mvp-contract-ru.md) — контракт PMS MVP версии 1.0 со статусом `Ready for implementation`.

При расхождении этого обзора с детальным контрактом соответствующего микросервиса приоритет имеет детальный контракт. Изменение границ владения между сервисами должно быть одновременно отражено в обоих контрактах.
