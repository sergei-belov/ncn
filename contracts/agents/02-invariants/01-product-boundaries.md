# Часть I. Границы продукта

## 1. Назначение системы

Мультиагентное ядро является сервисом оркестрации ИИ-агентов для системы управления проектами.

Ядро:

- принимает пользовательские запросы и системные инициаторы;
- формирует контекст выполнения;
- запускает координатора;
- делегирует подзадачи работникам;
- предоставляет агентам разрешённые инструменты;
- управляет долгоживущим исполнением;
- запрашивает подтверждение человека для рискованных действий;
- сохраняет состояние и журнал исполнения;
- возвращает итоговый текст и структурированный результат.

Ядро **не является** системой управления задачами, CRM, документооборотом или иным доменным сервисом. Изменение доменных данных выполняется только через внутренние MCP/API соответствующих сервисов.

## 2. Обязательный MVP-сценарий

Первый релиз должен реализовать полный минимальный happy path:

1. администратор проекта настраивает координатора;
2. администратор создаёт одного или нескольких работников;
3. агентам назначаются модели, инструкции, разрешённые MCP tools и доступ к памяти;
4. пользователь создаёт Session и отправляет сообщение;
5. создаётся Run с неизменяемым snapshot используемой конфигурации;
6. координатор анализирует запрос и формирует план;
7. координатор при необходимости вызывает работников;
8. агенты читают память и вызывают разрешённые MCP tools;
9. рискованный side effect приостанавливается до Approval;
10. выполнение продолжается после решения пользователя;
11. система сохраняет результат, события и usage;
12. пользователь получает итоговый ответ.

Automation-triggered запуск, визуальный конструктор Workflow, сложная событийная интеграция и расширенные административные функции не входят в обязательный первый вертикальный срез.

## 3. Что входит в MVP

В MVP входят:

- Project-scoped координатор;
- Project-scoped работники;
- CRUD и публикация конфигураций агентов;
- Session, Message и Run;
- динамический план координатора;
- последовательный запуск работников и ограниченный parallel join `all`;
- Temporal-managed orchestration;
- системные внутренние MCP;
- простые пользовательские MCP с API key или Basic Auth;
- централизованная проверка permissions в `agent-core`;
- Approval для рискованных операций;
- проектная память и базовый RAG;
- хранение артефактов;
- PostgreSQL как источник истины;
- аудит, tracing и usage accounting;
- базовые лимиты и защита от бесконечного исполнения.

## 4. Что не входит в MVP

В MVP не входят:

- OAuth пользовательских MCP;
- произвольные agent-to-agent handoff;
- вызов работником другого работника;
- отдельный planning/decision-agent;
- CEL runtime;
- полноценный JSONPath runtime;
- произвольные циклы в плане;
- сложные join-стратегии кроме `all`;
- полноценный no-code Workflow designer;
- reservation-based billing;
- Vault/KMS как обязательная зависимость;
- сложная ACL-модель RAG;
- индексирование секретов;
- автоматическое удаление business data по retention policy;
- микросервисное дробление `agent-core`;
- гарантия exactly-once для внешних side effects.
