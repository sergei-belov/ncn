## Введение

### 📘 Назначение документа

Этот документ описывает бизнес-логику, цели и ключевые возможности платформы **QAi** — интеллектуального инструмента для автоматизации тестирования веб-приложений с помощью больших языковых моделей (LLM).
Он предназначен для использования заинтересованными сторонами, в том числе:

* владельцами и менеджерами продуктовых команд,
* специалистами по качеству,
* техническими руководителями,
* инженерами по тестированию.

Документация создается в рамках раннего этапа разработки продукта и служит основой для понимания концепции платформы, её структуры и предполагаемой бизнес-ценности.

---

### 🎯 Цель платформы

Основная цель QAi — **оптимизировать затраты на тестирование** и **максимизировать ценность автотестов** за счет применения искусственного интеллекта.
Платформа позволяет быстро и с минимальными усилиями создавать автотесты, основанные на реальных пользовательских сценариях, и запускать их в автоматическом режиме. Это особенно актуально для продуктовых компаний, стремящихся обеспечить качество без чрезмерного роста QA-команды.

---

### 👥 Целевая аудитория

Платформа ориентирована на:

* **Продуктовые команды**, стремящиеся автоматизировать тестирование пользовательских сценариев;
* **Менеджеров по качеству**, ищущих инструменты для системного контроля над регрессиями;
* **Разработчиков**, которым необходимо оперативно проверять функциональность интерфейса без глубокого погружения в тестовые фреймворки.

Платформа наиболее ценна в условиях, где:

* важна скорость вывода продукта на рынок,
* часто вносятся изменения в интерфейс,
* отсутствуют ресурсы для построения масштабной QA-инфраструктуры.

---

### 🧱 Общее описание платформы

**QAi** предоставляет удобный веб-интерфейс для создания проектов тестирования. Внутри каждого проекта пользователь задаёт:

* ссылку на веб-приложение;
* переменные окружения (включая конфиденциальные);
* граф проекта: страницы, состояния DOM, действия, URL-нормализацию и связи достижимости;
* графы действий (user flows), представляющие собой набор шагов пользователя с ожидаемым поведением;
* черновики пайплайнов и опубликованные версии тест-кейсов для контролируемого запуска и отката;
* AI-generation session'ы, которые позволяют получить preview нового или измененного draft сценария до сохранения.

На основе графов действий и контекста страницы встроенная LLM-модель:

* автоматически генерирует абстрактный код для фреймворка Playwright;
* создает структурированные тест-кейсы;
* публикует неизменяемые версии тест-кейсов из редактируемых черновиков;
* запускает тесты и предоставляет понятный отчет;
* помогает строить информационный граф тестируемого приложения без прямого запуска тестов из графа;
* помогает пользователю генерировать и дорабатывать шаги через асинхронного агентного помощника.

Таким образом, пользователь получает автоматизированную воронку: **от описания сценария → к preview → к draft → к версии → к запуску → к результату** — без необходимости писать тесты вручную.
